## 一、这套系统是什么

### 1.1 它解决什么问题

阿里国际站新人业务员**上真实询盘之前**的陪练与闸门。

核心是把「敢不敢把真实商机交给这个人」这个判断，从主管的主观印象，
换成一套**每天都在跑、有据可查、能回放**的机制。

系统模拟真实后台：一封询盘进来、一张客户信息页、一段原文，业务员用中文写、
系统译成商务英语、客户（由大模型扮演）按**代码算出来的状态**回应。

### 1.2 三件事必须先分清

| | 演习（练习） | 考试 | 判定 |
|---|---|---|---|
| 干什么 | 练手，随便打 | 每天 1 场、3 局 | 决定他能不能接新询盘 |
| 分数进判定吗 | **不进** | **进，唯一材料** | — |
| 局数管什么 | **只管解锁当天的考试** | — | — |
| 谁触发 | 业务员自己 | 业务员自己（要先解锁） | 系统每晚 00:05 自动 |

**一句话**：演习只开闸门不进判定；判定只看考试局；判定挂在「日」上不挂在「场」上。

### 1.3 技术形态（管理员需要知道的部分）

| 项 | 现状 |
|---|---|
| 访问地址 | 部署后的网址（见 `部署/部署说明.md`） |
| 部署 | Next.js 应用 + PostgreSQL；可部署到 Vercel 一类托管平台，也可用 Docker 部署到自己的服务器 |
| 大模型 | DeepSeek（扮演/翻译/抽取走 flash，复盘出题/评分走 pro） |
| 定时结算 | 每天上海时间 **00:05** 自动跑（托管平台的定时任务，或服务器上的定时任务） |
| 本地开发 | `npm run dev`，端口 3100 |
| 有无自助注册 | **没有**。只有管理员能加人 |

## 二、一页看懂：一个人在系统里的一生

```
┌──────────────────────────── 一个人在系统里的一生 ────────────────────────────┐
│                                                                             │
│  管理员在【账号管理】加人（姓名 + 简码 + 身份）                                │
│        ↓                                                                    │
│  本人首次登录，自己设口令（管理员全程不碰口令）                                │
│        ↓                                                                    │
│  ┌── 实习业务员 / 准入模式 ──────────────┐   ┌── 正式业务员 / 周考模式 ──┐   │
│  │  期别 = 训练期（没有新询盘分配权）      │   │  每周 ≥2 场考试（6 局）    │   │
│  │        ↓                              │   │  随时可考，不要求先练      │   │
│  │  每天 ≥3 局【演习】→ 解锁当日考试       │   │  只记录，不动任何权限      │   │
│  │        ↓                              │   └──────────────────────────┘   │
│  │  每天 1 场【考试】= 3 局（标准探需 + 困难探需 + 跟进）                     │
│  │        ↓                （每局：对话 → 报价/背调 → 复盘五问 → 评分）      │
│  │  每晚 00:05【结算】：最近 2 个业务日共 6 局，局分中位数 ≥ 65 ？            │
│  │        ↓                                                                │
│  │  次一个业务日【生效】：达标 → 在岗期（可分配新询盘）                      │
│  │                       连续 2 天不达标 → 退回训练期（停发新询盘）          │
│  └─────────────────────────────────────────────────────────────────────────┘│
│        ↑                                                                    │
│  管理员在【教练台】盯：今日谁没考、谁掉期别、周考考满没有、难度系数             │
│  管理员在【账号管理】干预：改身份 / 改期别（只管当天）/ 停用 / 请假 / 重算      │
└─────────────────────────────────────────────────────────────────────────────┘
```

**「暂停」的确切含义**：只停掉**分配新询盘**的权利。
已经接到手上的客户仍归他，跟进不受任何影响。这一句要对业务员讲清楚。

## 三、身份模型与权限

### 3.1 四个字段，各回答一个问题

**页面权限**与**员工阶段**是彻底分开的两件事，任何一个都不许拿去猜另一个。

| 字段 | 取值 | 回答什么 | 谁改 |
|---|---|---|---|
| **角色** | 业务员 / 管理员 | **他能看见谁**（只看自己 / 看全员） | 管理员手动 |
| **身份** | 实习业务员 / 正式业务员 / 待确认 | **他是哪种员工** | 管理员手动 |
| **参与模式** | 准入训练 / 每周考试 / 不参加 | **他在干嘛** | **跟着身份自动写，不是独立开关** |
| **期别** | 训练期 / 在岗期 | **他有没有新询盘分配权** | 系统每晚判；管理员可覆盖当天 |

**身份自动联动（不用你管，也改不了）**：

```
实习业务员 → 参与模式 = 准入训练 → 有期别，走每日判定
正式业务员 → 参与模式 = 每周考试 → 不分期别，只记录周考
待确认    → 参与模式 = 不参加   → 什么都不做
```

> **管理员本人的身份是只读的**，跟着角色自动走，界面不给下拉框。
> 上一次事故就是手选选出来的：身份选成「正式业务员」而参与模式是「无」，
> 两个字段对不上，判定脚本报了半个月的口径错误；而管理员改不了自己，连自救都做不到。

### 3.2 权限矩阵

权限模型只有一条线：**是不是管理员**。全系统共用，没有第二套。

| 动作 | 业务员 | 管理员 | 定时任务 |
|---|---|---|---|
| 进【账号管理】、【教练台】 | ❌ 页面直接不存在 | ✅ | — |
| 加人 / 改角色 / 改身份 / 改期别 / 交回系统 / 重置口令 / 停用 / 删除 | ❌ | ✅ | — |
| 标假期 / 标调休 / 标请假 / 撤销 / 点重算 | ❌ | ✅ | — |
| 触发结算 | ❌ | ✅ | ✅ |
| 重算历史（破坏性） | ❌ | ✅ 必须显式确认 | ✅ |
| **在自己的局里发消息 / 报价 / 背调 / 评分** | ✅ 仅本人 | **❌ 管理员也不能替人聊** | — |
| 看别人的局与对话原文 | ❌ | ✅ | — |
| 台账导出 | 只能导自己 | 导全员 | — |
| 难度系数、考试题库、规则回放 | ❌ | ✅ | — |

**三条设计，别改坏**：

1. **每个操作自己查一遍身份**，不靠页面隐藏——接口能被直接调，藏 UI 不是权限。
2. **停用当场生效**：被停用的人当场登不进来，不等 30 天令牌过期。
3. **登录 cookie 是签名令牌，不是明文简码**——改一个字签名就对不上。

### 3.3 两道防呆闸

界面上有些按钮会「不动」，那是故意的：

1. **不许动自己**（改角色、改身份、停用、删除）；
2. **不许动最后一个还在用的管理员**（降权、停用、删除）。

少了任何一条，都可能把所有人关在管理页外面。

## 四、日常操作（按场景）

### 4.1 新人入职：开账号

**页面**：账号管理 → 最下面「加一个业务员」

填三样：

| 字段 | 规则 |
|---|---|
| **姓名** | 真名，会显示在所有台账上 |
| **简码** | 1–6 位字母或数字，自动转大写，**全系统唯一** |
| **身份** | 待确认 / 实习业务员 / 正式业务员 |

> ### ★ 简码定了几乎改不了 ★
> 它会长进每一局的演习 ID（`D-简码-人设-日期-序号`），历史分与标尺校准都挂在上面。
> **敲错了就趁他一局都没打过的时候删掉重加**——打过局之后就只能停用，删不掉。
>
> 撞码会明确报错「简码 XX 已被张三占用」，不会静默改掉在职同事的名字。

**加完之后要做的两件事**：

1. **让本人尽快登一次**。新账号没有口令，**谁先登谁就把口令定了**。
   管理员全程不碰任何人的口令，这是有意设计（设了也得口头传，传的路上就漏了，还得记）。
2. **确认身份填对了**。加人的那一刻会写下「起判锚点」——系统从这天之后才开始判他。

**加人一律先给「业务员」角色**，需要管理员权限的再单独改。

### 4.2 每天早上五分钟：教练台

按这个顺序看：

#### ① 待办条（最上面）

只放要立刻处理的三件事：

| 待办 | 你要做的 |
|---|---|
| **今日未考名单**（带演习进度） | 看进度决定是催练还是催考 |
| **今日期别变动** | 谁升了、谁掉了，掉的那个当天找他谈 |
| **工作日历还够用几天** | 少于 45 天橙色、少于 15 天红色 → 去补标假期 |

#### ② 今日判定表：一人一行

| 列 | 意思 |
|---|---|
| 期别 | 训练期 / 在岗期；橙字「今天主管定的」表示被人工覆盖着 |
| 演习 | 今天练了几局（分子只算有效局，见 [6.1](#61-演习与解锁闸门)） |
| 最近 2 天考试 6 局 · 中位数 | 六个格子 + 中位数 |
| 当日基本任务 | 今天的作业做完没 |
| 判定 | 达标 / 不达标 / 不构成判定 |
| **差在哪** | **最有用的一列**——差几分、缺哪天、是谁的问题 |

#### ③ 六个格子怎么读（一形一义，一色一动作）

```
┌─────── 前一个业务日 ───────┬────────── 今天 ─────────┐
│  第1局    第2局    第3局   │  第1局   第2局   第3局   │
└────────────────────────────┴─────────────────────────┘
        （颜色暗）                    （颜色亮）
```

| 符号 | 含义 | **你要做的** |
|---|---|---|
| `68` | 那一局考了 68 分 | 不用动 |
| **`✗` 红** | **有资格考却没来考** | **催他去「考」** |
| **`锁` 橙** | **那天演习没练够，考试没解锁** | **催他去「练」，不是催考** |
| `?` 灰 | 考了，但系统没评出分（证据不足） | **不记他的**，找开发 |
| `·` 淡 | 今天还没考到 / 那天他还没入职 | 什么都不用做 |
| 整行「请假」 | 那天对他不是业务日 | 什么都不用做 |

> **红＝催考试，橙＝催演习，灰＝不用管。**
> 这两件事要做的动作完全相反：
> 把「没资格考」写成「缺考」，是拿一件他做不到的事记他的账。

#### ④ 正式业务员 · 本周考试（另一张表）

一人一行：本周场次 N/2、出分局数 N/6、本周中位数、达标与否。

**这张表刻意不并进上面那张**——上面每一列都是准入口径，
硬塞进去会让人以为正式业务员也在被那套门槛判。

**正式业务员的周考只记录，不处罚**：不动期别、不动询盘分配权、不动正式段位。

#### ⑤ 局流水

全员的局（**含进行中的**），时间精确到秒。
进行中的局才是最该看见的——业务员正卡在哪，出分之后再看就晚了。

> **教练台的「今天」= 最近一个业务日**（周六打开看到的是周五的），
> 业务员那边的「今天」= 自然日。这是有意分叉，界面上标了「（今天休息）」。

### 4.3 催办：三种情况三种话

| 格子 | 他的问题 | 该说的话 |
|---|---|---|
| `锁` | 演习没练够 | 「你今天演习 2/3 局，考试还没解锁——**去练，不是去考**。一局要聊满 6 轮、出了报告、并且**真问出了东西**（至少解开一张暗牌，或至少开口问过一项六要素）才算一局。」★ 2026-08-28 改：第三条原来是「做完复盘」，复盘改可选后换掉 ★ |
| `✗` | 有资格但没考 | 「今天这场考试没开。**缺考直接算不达标，而且缺的局补不回来**，明天多考也填不进昨天那三格。」 |
| `?` | 系统没评出分 | 「**不是你的问题，也不记你不达标。**」然后去找开发。 |
| 分数不够 | 真的考砸了 | 看「差在哪」那一列，**给距离**：「距 65 差 4 分」能行动，「未达标」不能。 |

### 4.4 干预期别：人工改，只管当天

**页面**：账号管理 → 期别那一列

| 规则 | 内容 |
|---|---|
| 怎么设 | 选期别 + **必须填理由**，点「改」 |
| **有效期** | **只管设定当天**。今天的成绩一结算（明早 00:05），标记自动摘掉，系统接管 |
| 覆盖期间 | 每晚照算、照记、**不执行**。面板上会同时显示「系统算下来应该是 XX」——**两个数字打架的时候，人要看得见在打架** |
| 覆盖期间 | **不发横幅**给业务员（预警说的是「明天起将暂停」，而他被锁着，明天不会暂停。说一件不会发生的事比不说更糟） |
| 提前收手 | 点「**立刻交回系统**」，期别当场跳回系统算出来的那个 |
| 交回之后 | 系统不会撤销你改的——它只在**有明确判定**时才动人（达标 / 连着 2 天不达标） |
| 补算历史时 | 结算比设定日更早的日子时，你的人工设定**仍然作数**（拿前天的成绩推翻你今天的决定，那是倒着来） |

> ### ★ 为什么改成「只管当天」★
> 原规则是「一旦人工设定，自动判定永远不再改这个人」。实际跑下来是**主管改完就忘**，
> 人一直锁在在岗期，系统算出来该退训练期也不动，而没人记得去解锁。
> 现在：**你只对某一天负责，第二天交回系统**——你不可能每天盯着。

### 4.5 工作日历：假期、调休、请假

**页面**：账号管理最上面（默认折叠）→「工作日历」，**在月历上点日期**。
个人请假是并排的第二张月历，先选人和事由，再点日期。

**它只回答一件事：这一天上不上班。**

| 层 | 范围 | 例子 |
|---|---|---|
| **公司日历** | 全员 | 法定假期、**调休上班** |
| **个人请假** | 单人 | 病假、事假、出差、停用期 |

#### 五条铁律

1. **只存例外**。默认周一至周五上班、周末休息，和默认一样就不用标。
   （标一堆「和默认一样」的，「没维护」和「维护过」在数据上就分不开了——
   一张没人维护的全量日历，看起来和一张认真维护过的一模一样。）
2. **双向都要标**：既能标「放假」，也能标「**调休上班**」。
   中国的法定假期一定带调休（放 7 天配一个周末上班），
   **只能标假不能标调休的日历，一年至少错六次**。
   界面上因此只有一张日历，点哪天算哪天。
3. **放假那天整天从判定里消失**：台账没有那一行、不占任何人的窗口格子、
   当晚不结算、一行留档都不写。假期后第一天的「前一个业务日」自动接到节前那天。
4. **请假同上，但只对他一个人**。台账那一行写「**请假**」不是「缺考」——
   一个是批过的，一个是没来。
5. **假期 / 周末 / 请假当天打的局：照评不判**。
   照常评分、照常出报告，只是不进判定窗口。**这句话要跟加练的人讲**，
   不然他白打了还不知道（考前必读上已写）。

#### ★ 改了日历必须重算 ★

留档是当晚按**当时的**日历算的。改完日历，旧留档就过期了。

系统会做**三向体检**并在面板上报警：

| 检出的问题 | 意思 |
|---|---|
| 留档落在放假日 | 那天现在标着放假 / 周末，留档该删 |
| 留档落在请假日 | 那天他请假，留档该删 |
| 连续天数断链 | 连续不达标天数和前一天对不上（中间插过或删过日子） |

检出后给你一个「**从 X 起重算**」按钮。**系统不会自动重算**——
重算会真的改人的期别与分配权，一次手滑点错的日期若立刻连带改状态，
等于让一次误操作直接停掉某人的询盘。所以做成必须由人明确按下去。

**重算的限制**：一次最多 40 个业务日；没跑完会告诉你「从 X 再点一次」；
必须按日期从早到晚跑（连续天数是链式的）。重算会留痕，事后分得出
「系统判的」和「谁点的重算」。

### 4.6 忘了口令

点「**重置口令**」= **把口令清空**，不是设一个新的。本人下次登录时自己重设。

**口令规则**：≥6 位、≤64 位、不许纯数字。

### 4.7 停用 / 恢复 / 删除

| 动作 | 什么时候用 | 效果 |
|---|---|---|
| **停用** | 离职、产假、长病假、借调、外派 | 当场登不进来；停用期间**不结算、不判定**；台账与历史全部保留 |
| **恢复** | 人回来了 | 系统**先**把停用那几天自动写成请假（事由「停用期」），**再**放开账号 |
| **真删** | 只有简码敲错、刚加完就要撤 | 只对**一局都没开过、一次考试都没有**的账号开放 |

> ### ★ 离职走「停用」，别删 ★
> 一旦跑过局，他的台账就是团队资产：演习 ID 里长着他的简码，历史分、标尺校准都挂在上面。
> 数据库层面也拦着，硬删会直接报错。
>
> ### ★ 恢复的顺序系统已经处理好了 ★
> 停用期间不写留档是对的；但一旦恢复，补算会往回追 30 个业务日，
> 如果不先补请假，**会把停用那几天全部补判成「缺考、不达标」**，
> 连续 2 天就退回训练期——人回来上班第一天先被系统扣一次资格。
>
> 现在系统会自动先写请假再放开，**你只要点「恢复」就行，不用手工补**。
> 那些「停用期」的请假标记在工作日历上看得见，也撤得掉。

账号管理 → 身份那一列，下拉改成「正式业务员」。

## 六、规则与标准（判定引擎）

### 6.1 演习与解锁闸门

#### 什么算「一局有效演习」

三个条件同时满足：

1. 是演习局（不是考试局），且已结束；
2. **业务员自己说满 6 轮**（或客户提前离场）；
3. **出了分**（意味着复盘五问真的做完了——评分接口有硬闸，五答未齐直接拒绝）。

> **为什么底线是 6 轮 + 出分**：
> 只数「开过局」，开三局各发一句也算数，那这道闸门就只是三次点击；
> 只要 6 轮就算，那就是三次敷衍，成本只是一点 token。
>
> **这条底线必须写进界面文案**——不写，被拦住的人会以为是分数不够，
> 会反复去开新局，而他真正要做的是把上一局的复盘答完。（界面已写。）
>
> 注意：只要求「出了分」，**不要求「精确分」**——证据不足不是学员的错，
> 拿它挡解锁就是冤枉人。

#### 解锁当天考试的条件（只拦训练期的实习业务员）

| 条件 | 值 |
|---|---|
| 当日有效演习局数 | **≥ 3 局** |
| 其中至少几局不是简单局 | **≥ 1 局**（标准或困难） |

> **为什么加「至少 1 局非简单」**：简单档从 3 封扩到 18 封之后，
> 新人可以每天挑三局最容易的把考试解锁出来。
> 但也不能把简单局完全排除——那样扩出来的 18 封简单局对解锁毫无价值，练它等于白练。

**在岗期不要求演习**；**正式业务员不要求演习**（他的要求是每周 2 场，练不练自己定）。

#### 结构化训练任务（新人首个周期）

实习业务员加进来时自动生成 8 项任务，**顺序解锁**：

```
① 简单探需  ② 简单探需  ③ 标准探需  ④ 标准探需
⑤ 标准探需  ⑥ 困难探需  ⑦ 困难探需（带背调）  ⑧ 跟进局
```

任务的「有效局」判据比解锁闸门更严：要求已评分、报告已生成、复盘 5 题全答完且没跳过。

### 6.2 考试规则

#### 开考闸门

| 条件 | 适用 | 不满足时提示 |
|---|---|---|
| 必须走某条考试轨 | 两条轨 | 「当前账号不参加演习考试」 |
| **今天还没开过场** | 两条轨 | 「今天这场考完了 · 每人每天 1 场（3 局），明天再来」 |
| 今天那场没在进行中 | 两条轨 | 「今天这场还没打完」 |
| 训练期：当日有效演习 ≥3 局 | 仅准入轨 | 「演习 2/3 局，考试还没解锁」 |

> **「一天一场」两条轨都拦**：一天考多次就会一直刷分、没时间维护现有客户。
> 这个顾虑对正式业务员一样成立。
>
> **「当日先练 3 局」只拦准入轨**：那道闸是逼训练期的实习生每天刻意练习换一次考试机会。

#### 一场考试 = 3 局

| 槽位 | 内容 |
|---|---|
| 第 1 局 | 探需 · **标准** |
| 第 2 局 | 探需 · **困难** |
| 第 3 局 | **跟进局** |

#### 选题：四道防重复

| 约束 | 规则 |
|---|---|
| 池子 | **只从准入考试池取**，每槽至少 14 份**且至少 4 个考点**，否则直接报错。★ 2026-08-28 加了考点门槛 ★ 14 份题可以全部来自 3 个考点——那不是抽题，是轮流；考点数低于 8 教练台告警 |
| **禁止回退** | 考试池不足**绝不允许**回退练习池 |
| 版本唯一 | 活动的题池版本只能有一个，多于一个直接报错 |
| 防重复 | ① 排除本人**所有**考试局用过的变体（2026-08-28 从「最近 14 局」扩大——原来约 5 天就解禁，且那 14 局里还混着演习局）；② 排除**上一场**用过的人设骨架；③ 本场三局骨架互不相同；④ 抽题**先在考点里等概率、再在变体里等概率**（2026-08-28 加：原来在变体里均匀，变体多的考点多拿彩票，困难槽的 P19 占到 43%） |
| 随机 | 每个槽位在候选里**随机**取——固定顺序等于可透题 |

**正式业务员的周考抽同一个池**：同一把尺、同一批题，两类人的分数可直接横向比。

#### 一天一场，考完就锁

- 开考瞬间 **3 局全部生成好**，可以关掉浏览器分次打，当天回来接着打，不会丢。
- **不能重开一场，也不要跨天**。跨天未结算的场次会被自动结算或作废，
  **但已经打完并出分的局照常进判定窗口，一局都不浪费**。
- **判定不读考试的结算状态，只读「局」和「分」**。

> 过去交卷要考生自己点「结算本组」——等于**让被判的人决定什么时候被判**，
> 一个自觉考砸的人只要不点，状态就永远停在在岗期。这个洞已彻底堵掉：
> 就算自动交卷失败也不影响任何判定。

### 6.3 判定窗口：按天排死的 6 个格子

#### 哪些局算数

| 局 | 进判定窗口？ |
|---|---|
| 演习局 | **不进**（只开闸门，只看局数不看分数） |
| **考试局** | **进 —— 判定的唯一材料** |
| v2.0 历史考试局 | 不进（口径不同的分不可比） |

还必须**已评分**。

#### 四条铁律

1. **锚是日期，不是局数**——那天没考，那三格就空着，**不会往前多捞几局把窗口填满**。
2. **一天最多认 3 局，且认当天最早的 3 局**——否则考砸了再开一场就能把前面的挤出窗口，等于允许刷分。
3. **只认工作日**——周末、公司放假、他本人请假，三样都跳过。
4. **空格补不回来**——明天再考三局也填不进昨天那三格。

#### 判定条件：只有一条

| 条件 | 口径 | 阈值 |
|---|---|---|
| 局分 | 窗口 6 局的**中位数** | **≥ 65**（D4 进阶期下沿） |

> 洞察力中位数 ≥3、最近 2 天无生效红线、复盘作答质量中位数 ≥1
> 这三条**照常算、照常存、照常写进报告**，但 2026-08-21 起**不参与「过没过」**。
> 要加回来是改一个配置数组的事，界面的列会跟着自动变。**这个要找开发。**

#### 判定流程

```
6 格都有局？ ──否──→ 缺考 / 未解锁 → 不达标，连续天数 +1
      │是
      ↓
6 局都有精确局分？ ──否──→ 不构成判定（证据不足，不算他的）
      │是
      ↓
中位数 ≥ 65 ？ ──否──→ 不达标，连续天数 +1
      │是
      ↓
   达标，连续天数清零
```

#### 结论是三态，不是「过 / 不过」

| 结论 | 什么情况 | 连续不达标天数 | 期别 |
|---|---|---|---|
| **达标** | 6 局齐、中位数 ≥65 | **清零** | 训练期 → 在岗期 |
| **不达标** | 中位数不够 **／缺考 ／未解锁** | **+1** | 连续 ≥2 天 → 退回训练期 |
| **不构成判定** | 今天还没考完；考了但没评出分 | **不加也不清零** | 不变 |

> ### ★ 缺考算不达标 ★（2026-08-22 定）
> 原话：「缺考肯定算不达标啊……如果缺考都能算达标的话，那大家都不考了呀。」
>
> 在这之前，**缺考是保住资格的最优策略**——不考就永远判不出来，
> 连续天数不涨，分配权永远不掉。
> 病假误伤由工作日历那一层挡（请假当天根本不进窗口）。

#### 措辞标准（对业务员讲的话）

**未达标一律给距离。**「距 65 差 4 分」能行动，「未达标」不能。

| 情况 | 该说的 |
|---|---|
| 缺考 | 「2026-08-20 整天缺考。缺的局补不回来；连着考满两天才会重新达标。」 |
| 未解锁 | 「演习 2/3 局，考试没解锁——不是缺考，是当天没资格考；**要催的是演习**。」 |
| 证据不足 | 「6 局都考了，但有 1 局证据不足……**这不是你的问题，也不记不达标。**」 |
| 今天还没考完 | 「今天还没考完（还差 3 局），考满 3 局才出判定。」 |

**要读出的五件事**：

1. **08-03**：新人第一天不可能达标——窗口一半是空的。这是 6 局窗口的必然代价，不是他考砸了。
2. **08-04**：中位数正好 65 算过。**压线通过是有意的，不是 bug。**
3. **08-06**：连续第 2 天不达标才动资格。**一天失手拉不垮。**
4. **08-07**：演习没练够 → 未解锁 → 不判定，期别不变，连续天数停在 2（既不加也不清零）。
5. **08-10**：他这天考得很好（中位 70），**依然不判定**——因为 08-07 那三格是空的。
   **缺一天连累两天。**

### 6.4 结算与生效时序

```
D 当天白天  ：不结算 D。教练台「今日判定」是现算的，只给主管看，不改任何人的状态。
D 当晚 00:05：结算 D —— 读 D 及之前的局，算结论，写留档。
D 的次业务日：结论生效，改期别与分配权，业务员登录时看到横幅。
```

**四种横幅**（业务员次日登录时首页顶部）：

| 情况 | 横幅 |
|---|---|
| 训练期 → 在岗期 | 获得询盘分配权 |
| 在岗期且达标 | 保留 |
| 在岗期不达标且连续 ≥1 天 | **预警：再有一天就暂停** |
| 在岗期 → 训练期 | 暂停分配新询盘 |
| 人工锁定期间 | **一律不发横幅** |

#### 起判锚点与补算

| 机制 | 规则 |
|---|---|
| **起判锚点** | 取「身份定下来那天」与「他第一场考试那天」里**更早**的一个；**起点日当天不判**（那天他多半是半路进来的） |
| **幂等** | 同一个（人，日）只有一行，重复跑只更新 |
| **补算** | 定时任务会漏跑（部署窗口、冷启动、免费额度），所以首页 / 考试页 / 教练台 / 账号管理四个页面被打开时也各补一次，往回追 **30 个业务日** |
| **不结算的情况** | 停用期间、公司放假、他本人请假、起判锚点之前——**一行留档都不写** |

> **为什么不写留档**：硬写一行会在台账上留下一片「不构成判定」，
> 让人以为系统那几天出了问题。

### 6.5 正式业务员：周考

| 项 | 规则 |
|---|---|
| 要求 | **每周至少 2 场**考试，一场 3 局，合计 **6 局出分**。周一到周日算一周（自然周） |
| 每日上限 | **每人每天 1 场**，与实习业务员同一道闸 |
| 开考前置 | **无**。不要求当日先练够几局 |
| 练习 | **不限次数、不计入周考**。只有考试闸门开出来的局才进统计 |
| 题池 | **与准入考试同一个池、同一把尺、同一套防重复** |
| 中位数 | 本周已出分考试局的中位数。**65 是参考线不是门槛** |
| **后果** | **只记录，不处罚**——不动期别、不动询盘分配权、不动正式段位 |
| 结论三态 | 考够了 / 这一周已过完但没考够 / **这一周还没过完（不构成结论）** |
| 结算 | 挂在每晚 00:05 那趟任务上，周一那趟把上一周封板 |
| 看哪儿 | 本人：首页周考卡、考试页、训练台；管理员：教练台「正式业务员 · 本周考试」；导出：台账「正式业务员周考」sheet |

> **周考刻意没有「连续不达标」和横幅**——那两样是准入用来停询盘的，
> 抄过来迟早会有人顺手接上处罚逻辑。

### 6.6 难度系数：全系统唯一的松紧旋钮

**页面**：教练台最下面「难度系数」（默认展开）

| 规则 | 内容 |
|---|---|
| **达标线永远是 65** | 系数**不会**改这条线 |
| 系数调的是什么 | **拿到 65 分有多难**。系数越大，同样的表现分数越低 |
| 折算公式 | 最终局分 = 100 ×（原始分 ÷ 100）^ 系数 |
| **1.0** | **= 现在的标准** |
| 怎么调 | 先按 1.0 跑几天看分数分布——普遍偏高就往上加一档，偏低就往下减一档 |
| **真正要看的数** | 面板上那句「**业务员要打出 X 分的水平，才拿得到 65 分**」，X 才是你实际在调的东西 |
| 折算之后 | 折算后的分才是全系统认的局分：段位 D1–D5、红旗、中位数、准入判定，读的都是它 |
| 原始分 | 照常存着。折算过的局，报告里会写明「原始 70 → 系数 1.2 → 最终 65」，不会让人以为分是凭空少的 |
| **生效时刻** | **次一个业务日生效**。今天已开的局、已考的场仍按开局时的系数出分——同一场考试的三局要一起算中位数，不能落到两套口径上 |
| 留痕 | 每次调整排一行历史（含理由），只增不改；每一局按哪个系数打的记在这一局上 |

**调之前请填「调节理由」**——将来回溯全靠它。

## 七、评分标准

### 7.1 七力与权重

| 力 | 探需局权重 | 跟进局权重 |
|---|---|---|
| **洞察力** | **0.30** | 0.25 |
| **引导力** | 0.20 | 0.15 |
| **方案力** | 0.15 | 0.20 |
| **信任力** | 0.10 | 0.10 |
| **闭环力** | 0.10 | 0.10 |
| **博弈力** | 0.05 | 0.10 |
| **稳定力** | 0.10 | 0.10 |

**评哪几力由人设说了算**——不是所有局都评七力。
比如极限压价型的人设主考博弈力，首响过慢型的主考稳定力，
与本局无关的力标记为「本局不评」，退出分母。

> 早期评分接口把七力写死成同一套配置，对所有人设一视同仁——
> 极限压价型的**博弈力不评**、首响过慢型的**稳定力不评**，
> 而那恰恰是这两个骨架的主考点。现在读不到人设配置就**拒绝评分并要求重新装入题库**，
> 不顶默认值糊弄过去。

### 7.2 三道保证分数可信的关卡

| 关卡 | 做什么 | 不过会怎样 |
|---|---|---|
| **① 引文校验** | 模型给每个维度打分时必须附「第几轮、原话是什么」，系统**逐条回原文核对** | 引不出原话的维度直接判为「证据不足」，退出分母 |
| **② 覆盖率门槛** | 覆盖率 ≥ 0.60 | 不给分数，只给一句理由 |
| **③ 维度数门槛** | 可评维度 ≥ 4 | 同上 |

> **样本不足时给一个精确到个位的分数，比不给分更有害——它看起来很客观。**
>
> 没有引文校验这一步，「强制取证」就只是 prompt 里的一句空话——模型会编出看起来很像的引文。

### 7.3 局分与演习段位 D

```
加权能力分 = Σ(得分 × 权重) ÷ Σ(可评权重)
原始局分   = (加权能力分 − 1) ÷ 4 × 100        ← 纯代码算，不让模型做算术
最终局分   = 100 × (原始局分 ÷ 100) ^ 难度系数
```

| 段位 | 名称 | 区间 |
|---|---|---|
| D1 | 起步期 | 0–24 |
| D2 | 成长期 | 25–49 |
| D3 | 熟练期 | 50–64 |
| **D4** | **进阶期** | **65–79** ← **准入门槛正是 D4 下沿** |
| D5 | 专家期 | 80–100 |

> ### ★ 三条命名铁律，永不突破 ★
> 1. 演习分数叫**演习段位 D**，**永不写作 L**（有脚本扫源码强制）；
> 2. 演习局的数据**物理隔离**，不写进正式段位的记忆库；
> 3. 考试通过的结论只有一句：**「已获得询盘接待准入资格」**，
>    **不得表述为「达到 L2/L3」**。
>
> 演习段位 D 与正式段位 L 同引擎、同锚点、同阈值，但**不同池子**，不可混谈。

#### 为什么不重算历史局的分

七力分是模型打的，重跑会得到第三个版本——既不是当初那个分，也不是所谓「正确的分」。
而且准入结论一旦发出去，人当天就去接真实询盘了，撤不回来。

**不同口径的分不可比，别混在一起算中位数。**

### 7.4 两面红旗

| 红旗 | 触发条件 | 含义 |
|---|---|---|
| **高招式 · 零推进** | 局分 ≥60 但即时推进度 = 0 | 话说得漂亮，订单一步没往前走 |
| **高分 · 零认知** | 局分 ≥60 但复盘作答质量 = 0 | 打得好但说不出为什么 |

> **没做复盘问答就不许有作答质量**——「答不上来」和「压根没问过他」是两回事，
> 混为一谈等于凭空给人扣一顶帽子。

### 7.5 四条红线

| 代号 | 名字 | 判定来源 | 可靠性 |
|---|---|---|---|
| **R1** | 数量未确认即报价 | 纯代码 | 100% |
| **R2** | 疑罪从有（凭怀疑降低投入） | 模型自由评分 | 中 |
| **R3** | 空催（跟进不带任何新信息） | 结构化抽取 + 模型确认 | 高但非满 |
| **R4** | 用中文作答（直接把中文发给客户） | 纯代码 | 100% |

**红线现在不判任何人的生死**（2026-08-24 起）：

- 红线只进**报告**与**客户情绪值**：扣信任 / 耐心 / 兴趣 → 客户提前离场 → **局分自然变低**。
  这是它现在唯一的影响路径，且是**间接**的。
- **人工复核队列已整个取消**。代价说清楚：R2/R3 是模型判的、会有误报，
  而误报**不再有人能翻案**；之所以能接受，是因为判错一次的代价是报告里一句话说重了，
  不是一个人的上岗资格。
- 留痕仍在写，要查「模型这个月判了多少条 R3、准不准」，找开发查库。
- 演习局与考试局**一视同仁**，都照常检测、照常写进报告。

### 7.6 客户状态机（业务员看不到，你要知道）

客户有三个值，都夹在 0–100：**耐心**（初始 100）、**信任**（初始 50）、**兴趣**（人设给）。

| 加分行为 | 效果 |
|---|---|
| 首轮直接回应 | 信任 +10 |
| 利他外壳提问 | 信任 +15 |
| 选择题式提问 | 耐心 +5 |
| 肯定 / 认同客户 | 信任 +10 |
| 报价格式合规 | 信任 +15 |
| 跟进带新信息 | 耐心 +10 |

| 扣分行为 | 效果 |
|---|---|
| **未确认数量就报价（R1）** | **信任 −30** |
| **凭怀疑降低投入（R2）** | **兴趣 −40** |
| **空催（R3）** | **耐心 −25** |
| 未挖属性就报价 | 耐心 −20 |
| 没问需求先甩目录 | 兴趣 −20 |
| 整轮不抛问题 | 耐心 −10 |
| 大额报价只回一行字 | 信任 −25 |
| 信任低时冷脸质问矛盾点 | 信任 −20 |
| 拿错误背调结论当实锤质问 | 信任 −20 |
| 第一封开发信带图 / 视频 | 耐心 −10 |
| **每轮自然衰减** | **耐心 −5** |

**客户离场三条**（任一命中即结束）：耐心 ≤0 ／ 连续 3 轮无新信息 ／ 探需局超 20 轮仍未报价。

**客户的态度随耐心变**：耐心 ≥70 正常；<70 回复变短；<40 明显不耐烦、可能催价；≤0 直接走人。

> **这些数值是拍脑袋的初值，不是真理。** 需求给的是相对关系（裸报价最重、空催次重），
> 绝对值要靠回放调（教练台有回放工具，可批量重放历史局看结局变化）。

**报价分档**：A ≤100、B ≤300、C >300 USD。
金额 >300 USD 且既无报价表又无截图 → 判「一行字大额报价」扣信任。

### 7.7 背调子系统

每份背调包都**预埋一个张冠李戴的错误结论**——那是「AI 会乱抓，你要自己有判断」这个考点的载体。

- 材料四件：AI 报告、假官网快照、假社媒、联系方式。
- **识破路径**：发起过背调 + 查过至少一项交叉验证材料 + 本轮用矛盾点提问 → 判为识破
  （洞察力满分的达成路径之一）。
- **拿错误结论当实锤去质问客户** → 客户困惑，扣信任 20。
- 预埋的错误答案**永不出服务端**，前端 F12 也看不到。

### 7.8 复盘五问（v2.0 的灵魂机制）

| 规则 | 内容 |
|---|---|
| 题目构成 | **3 道针对性 + 2 道固定**。固定两题一字不改：①「这一局推进订单最大的阻力是什么？」②「如果重来，下一步你应该怎么回？」 |
| 出题角度 | 从 7 个角度里选 3 个不同的，每题**必须扎在这一局真实发生的事上并引用具体轮次**，不许夹带答案 |
| 提问方式 | **一次只问一个**——5 题全列出来，新人会扫一眼挑简单的答、互相参照着编 |
| 追问 | 答得含糊触发一次追问，**只追一次，不递归** |
| 左侧 | 摆着这一局的完整聊天记录（凭印象编出来的答案没有复盘价值） |
| ~~**硬闸**~~ | ~~未答满就不许评分~~ **2026-08-28 拆掉**：复盘作答质量本来就不计分（08-19 裁定），再卡在评分前面就是「必须做、但做不做不改变任何结果」，那种环节最后一定被敷衍。现在演习局与考试局都可跳过，跳过照常留痕、报告标「因未作答，以下判断为系统推断」 |
| 考试局 | **不可跳过**（前后端都拦） |

> 这是 v2.0 区别于 v1.0 的关键：v1.0 局一结束直接吐报告，新人被动接收结论——
> 与教练方式正好相反：「提问是为了拿到业务员脑子里的信息和想法，**没拿到答案之前，不做诊断**。」

## 八、系统维护与运维

> 这一节写给管理员做决策，具体命令由开发执行。

### 8.1 环境变量（改了要在线上和本地各配一遍）

| 变量 | 作用 | 不配会怎样 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 大模型密钥 | 对话、评分全部不能用 |
| `LLM_BASE_URL` | 模型地址 | 同上 |
| `MODEL_EXTRACT` / `MODEL_TRANSLATE` / `MODEL_ROLEPLAY` | 走 flash（便宜快） | — |
| `MODEL_COACH_QA` / `MODEL_SCORE` | 走 pro（复盘出题、评分） | — |
| `PRICE_*`（六个单价） | 成本台账 | **成本台账一直是 0，而且不报错** |
| `DATABASE_URL` | 数据库。云数据库建议用连接池串（如 Neon 主机名带 `-pooler` 的那个） | 直连可能把连接数吃满 |
| `AUTH_SECRET` | 会话令牌签名，**至少 32 位** | **没有默认值，少于 32 位直接启动报错**（有默认值等于所有部署共用一把钥匙） |
| `BOOTSTRAP_TOKEN` | 初始化接口令牌 | 不配 = 该接口自动禁用（这是安全的默认） |
| `CRON_SECRET` | 每晚结算的定时任务口令 | 不设也能跑（页面被打开时会补算），**但正式环境请设** |
| `BACKUP_DATABASE_URL` | 备份用的**直连**串 | 不填就只备本地开发库 |
| `LLM_DAILY_TOKEN_BUDGET` | **每日 token 预算闸**。不填＝ 500 万/天 | 不填就用默认值（够正常用一倍余量）。**填 0 ＝ 关掉这道闸**，只建议本地调试用 |

> ### ★ 别改 `DATABASE_URL` 去做备份 ★
> 改了它，本地开发就直接连上线上库了——一次误操作就能把线上数据改掉，
> 而且不会有任何提示。备份脚本专门认 `BACKUP_DATABASE_URL` 就是为了不让人动那一个。

> ### ★ 模型预算闸：什么时候你会看见它 ★（2026-08-28 加）
> 系统每天统计模型 token 用量，**到 70% 在服务端日志打一条 warn，到 100% 才拒绝新的对话**。
>
> - **业务员看到的**：「今天的模型用量已经到上限，暂时开不了新的对话。**这不是你的问题**……」
>   已经打完的局与分数不受影响，明天零点自动恢复。
> - **你要做的**：先想「今天是不是有东西在跑飞」——正常用达不到这个量（满负荷 7 人约 230 万，
>   闸设在 500 万）。确认是正常增长（比如人数翻倍），才去调 `LLM_DAILY_TOKEN_BUDGET`。
> - **★ 别一撞线就调高 ★** 这道闸唯一的作用就是拦住失控的调用。习惯性调高，等于把它关掉。

### 8.2 定时结算

- 配置在 `vercel.json`：`5 16 * * *`（**UTC**）= 上海 **00:05**。
- 界面上写的时间是另一个常量。**两处必须一起改**——
  改了一处没改另一处，页面上就会写着一个时间、实际跑在另一个时间，而没有任何东西会报错。
- 定时任务会漏跑（部署窗口、冷启动、免费额度），所以四个页面被打开时也各补算一次。

### 8.3 题库维护

**系统本身不带题。** 题目来自你们公司自己的聊天记录，加工成「题库包」后装进来；题库包是真源，一经装入不再修改，改题就装一个新版本。
格式见 [`题库格式规范.md`](题库格式规范.md)。

**日常在网页上做：顶部导航「题库工坊」**（只有主管和管理员看得到；凡是要拍板的事都是选择题，推荐项排第一）。

| 页 | 做什么 |
|---|---|
| 投料 | 拖进阿里国际站聊天导出件、产品表、公司信息表。**脱敏在你自己的浏览器里完成**，服务器只收脱敏后的内容。投多少份都行；开工前会报预计花费，第一批推荐先做 5 份看效果 |
| 加工 | 每一批、每一份走到哪、卡在哪。加工在服务器后台跑，关页面不停；中断了点「继续加工」从断点接着跑 |
| 确认 | 每道题一张卡：上半部分 30 秒看完的摘要，下半部分「采用 / 退回修订 / 弃用 / 其他」。演习题可以一键按推荐处理，考试题必须逐道确认 |
| 题库 | 打包上架（在当前版本上加题）、装入 / 切换 / 回滚、上传题库包、导出（可剥掉来源备注）、停用某道题 |
| 覆盖 | 55 型各几道、考试三个槽位还差什么、缺的题型该找什么样的聊天 |
| 回流 | 每道题的实战通过率、平均分、常见失分点；太容易、太难、总被同一句话破解的题出回炉建议：回炉 / 降为演习 / 下架 / 保留 |

部署在托管平台（如 Vercel）上时，工坊只开「题库」「覆盖」「回流」三页：在本机做好题库包，再到「题库」页上传装入。

**命令行**（批量、运维、排查用，和网页调的是同一套接口）：

| 想干什么 | 怎么做 |
|---|---|
| 装入题库包 | `npm run bank -- load <题库包目录>`：先校验（结构、考纲、引用、校验和），再写库、冒烟，最后切换为当前版本。云端部署可用环境变量 `BANK_DIR` 在初始化时自动装入 |
| 只校验不装入 | `npm run bank -- validate <题库包目录>` |
| 看装过哪些版本 | `npm run bank -- list`（★ 标的是当前版本） |
| 切换或回滚版本 | `npm run bank -- activate <题库编号> <版本号>`。旧版本的题保留在库里，历史局、报告照常能打开；正在打的局不受影响 |
| 看池子够不够 | 教练台 →「考试题库」，三个槽位各有几套一目了然；槽位为空会红字警告「缺！这个槽位没题，考试开不成」 |
| 上线前检查 | 跑 `npm run check:readiness`（见附录 C） |
| 检查库里的题型与考纲一致 | 跑 `npm run check:syllabus` |
| 命令行加工题库 | `npm run drawer -- ingest / run / reviews / pack`，说明见 [`操作单/抽屉使用说明.md`](操作单/抽屉使用说明.md)。**原始记录不出本机，脱敏在本机跑，AI 只碰脱敏后的素材** |

**发布或题库变更前必跑的检查**（任何一项失败都不得开放对应任务）：

```
npm run verify        # 测试 + 各项自检（含模块边界、考纲文档、版本号）
npx tsc --noEmit      # 类型
npm run build         # 构建
npm run check:readiness      # 题池、版本、账号身份门槛
npm run check:syllabus # 库里的题型与考纲一致
npm run release:check  # 对外发布（开源、交付客户）前：题目、密钥、客户黑名单、版本号、许可证
```

`check:readiness` 检查这些：练习池里有题、活动版本恰好 1 个、考题标记不错位、没有未确认身份的在用账号、正式业务员的口径没错。
准入池三个槽位的题数与题型数（门槛在 `standards/pool-requirements.json`，默认每槽 ≥14 道且 ≥4 个题型）没达到时，列成「考试暂未开放」提示，不算检查失败——演习照常能用，凑齐前只是开不了考。

> **尤其禁止考试池不足时回退练习池。**

#### ★ 题型由考纲决定，题库只能往现有题型里加题 ★

**题型是这套系统里最贵的东西，也是唯一的横向可比口径。** 考纲 v3 共 55 个题型，定义在 `standards/syllabus/`，
客户的聊天记录加工出来的题，只能挂在现有题型下面。

任何人如果绕过这条规矩加了题型或改了题型，会连锁塌掉四件事：

1. 考试三个槽位与池健康的假设全部失效；
2. 七力覆盖不再可验证：新题型自带一套「评哪几力」，没人审过它评的是不是那一力；
3. 难度带失去参照系——机制难度指数是**相对**的，比的是同池兄弟；
4. 跨公司比较彻底没了：A 公司的 65 分和 B 公司的 65 分不再是同一件事。

**所以题型行一律按考纲写**：装入题库时，题型的名称、考点、局型、默认难度、七力都取自考纲，题目自己写的字段改不到它；题目里写了考纲没有的题型编码，装入会被拒绝。

| 情况 | 该怎么办 |
|---|---|
| 想要「同一个题型的困难版」 | 用**题目级难度**（题目顶层的 `difficulty`） |
| 确实要新增/修改题型 | 这是一次**考纲改版**，由王老师拍板：改 `standards/syllabus/syllabus-v3.json` → `npm run gen:syllabus-doc` → 升考纲版本与项目版本 |

当前考纲：**v2**（55 个题型）。

### 8.4 备份与恢复

> **判定留档与对话记录是这套系统的全部历史资产，库没了重建不出来**：
> 分数是模型打的，重跑会得到第三个版本；准入结论一旦发出去，人当天就去接真实询盘了，撤不回来；
> 标尺校准、审计流水，全是人一条一条攒出来的。
>
> **云服务商的时间点恢复不是备份**，那是事故缓冲，窗口很短，账号本身出问题时它一起没。

#### 三条命令

```bash
npm run backup           # 备份
npm run backup:verify    # ★ 真恢复一遍 ★ 起干净容器 → 灌进去 → 逐表比对行数
npm run backup:verify -- <某个文件名>
```

备份存在 `<项目根目录的上一层>/_数据库备份/`（**在代码仓库外面**），每份两个文件：
`.dump`（数据）+ 同名 `.json`（清单：时间、来源、大小、校验和、**逐表行数**、验证时间）。

**那份 `.json` 不是装饰——恢复验证就是拿它对账。**
没有它，你只能知道「文件在」，不知道「数据全不全」。

#### 库出事了怎么办

1. **先别急着恢复，先确认三件事**：
   - 是数据没了，还是连不上？连不上是云服务的事，去控制台看，别急着灌数据。
   - 最新那份备份是什么时候的？**从那一刻到现在的数据找不回来**——
     先想清楚这段时间发生过什么（谁考过试、谁的期别被改过），恢复完要手工补。
   - 那份备份验过没有？看 `.json` 里的验证时间字段。
2. **先在本地验一遍**：`npm run backup:verify -- <文件名>`。
   这一步过不了，说明备份本身有问题，往线上灌只会把事情弄得更糟。
3. **灌进一个新库**，再把新库的连接串写回线上环境变量，重新部署。

详细命令见 `部署/备份与恢复.md`。

#### 频率

现在是**手动**。要自动，可在 Windows 任务计划里加一条每天 03:00 的任务。

> **这台机器关机的时候不会跑**——这是当前方案最大的短板，写在这儿别自欺欺人。
> 折中做法：任务计划照加，**再把 `_数据库备份/` 目录挂进网盘同步**。
>
> **每月至少跑一次 `npm run backup:verify`。**
> 备份机制烂掉的方式从来不是「报错」，是「一直在跑、一直没人验、
> 需要的那天发现导出来的是空的」。

### 8.5 审计流水

**账号管理页最下面「管理动作流水」**，只增不改不删。

十个动作全记：加人、删除、停用、恢复、改角色、改身份、重置口令、

## 九、异常处理（照着查）

### 9.1 「他明明练了三局，考试还是开不了」

按顺序查：

1. **是不是有局光聊没问**？有效局要求「聊满 6 轮 + 出了分 + 真问出了东西」，
   而出分要求复盘五问全答完。**进度没涨，多半是有一局的复盘没答完。**
2. **是不是三局都是简单局**？规则要求 3 局里至少 1 局是标准或困难。
3. **是不是有局聊得太短**？业务员自己要说满 6 轮。
4. **他是不是在岗期**？在岗期不需要演习，直接能考——那问题在别处。

### 9.2 「某人的期别莫名其妙掉了」

1. 打开教练台**历史台账**，找到掉的那两天，看六个格子——是缺考（`✗`）、
   未解锁（`锁`），还是分数不够。
2. 打开账号管理**管理动作流水**，看那几天有没有人改过身份、停用过、标过日历。
3. 看那几天**是不是应该请假 / 放假但没标**。是的话：补标 → 用「从 X 起重算」按钮重算。
4. 记住「**缺一天连累两天**」：窗口是 2 个业务日，昨天缺考，今天考得再好也判不出来。

### 9.3 「格子里全是 `?`（证据不足）」

**这不是业务员的问题，是系统没评出分。** 找开发。可能原因：

- 模型引不出原话（引文校验没过）→ 覆盖率不够 → 拒绝出分；
- 人设的七力配置读不到 → 系统会**拒绝评分并要求重新装入题库**（不会顶个默认值糊弄过去）；
- 模型服务抖动。

**证据不足不记他不达标，但会挡住他当天拿达标**（因为要求 6 局全有精确分）。

### 9.4 「改完工作日历，台账还是老样子」

**这是对的，系统不自动重算。** 面板上会出现三向体检的告警和「从 X 起重算」按钮，
你必须明确点下去。重算会真的改期别与分配权，所以不做成自动。

### 9.5 「重算跑了一半停了」

一次最多 40 个业务日。接口 / 界面会告诉你「还没跑完，从 X 再点一次」。
**必须按日期从早到晚跑**——连续不达标天数是链式的。

### 9.6 「考试开不成 / 报错」

去教练台「考试题库」看三个槽位的份数。任一槽位不足 14 份，考试直接抛错。
**绝不会回退到练习池**（那等于用练习题当考题）。找开发补题池。

### 9.7 「有人说自己周末打的局白打了」

**照评不判**：周末 / 假期 / 请假当天打的局照常评分、照常出报告，只是不进判定窗口。
这句话考前必读上写着，但值得当面再讲一遍。

### 9.8 「一个人三天没登录了」

登录流水会告诉你。**那比任何分数都先说明问题。**

### 9.9 「他说发出去的话没反应」

模型服务抖动时整轮会作废（宁可白花一次调用，也绝不写出一条前言不搭后语的时间线）。
让他重发一次。同一条消息重复提交不会产生两轮。

## 十、红线：管理员不能做的事

| 不要做 | 为什么 |
|---|---|
| **不要替业务员聊天、报价、评分** | 系统在权限上就拦着（管理员也不行）。替人聊出来的分是假的，会污染整条判定链 |
| **不要把简码改掉** | 它长在每一局的演习 ID 里，改了历史台账全对不上 |
| **不要删有记录的账号** | 离职走「停用」。数据库层面也拦着 |
| **不要把「规则回放」页给业务员看** | 它把扣分规则原样摆出来，等于把答案发给考生 |
| **不要在业务员面前打开教练台的「考试题库」** | 考题出现在别处等于泄题 |
| **不要把这份说明书发给业务员** | 阈值、扣分表、背调预埋错误、防重复规则，全在里面 |
| **不要改 `DATABASE_URL` 去做备份** | 那等于让本地开发直连线上库 |
| **不要用浏览器地址栏去触发重算** | 已被系统拒绝（只认 POST + 显式确认），别绕 |
| **不要「临时关掉判定」** | 系统会直接报错拒绝——把判定条件清空不是「谁都判不了」，而是「全员当场达标、界面一片绿」 |
| **改了阈值不要只改一处** | 配置、代码、文档三处要一起动。少动一处，界面上就会同时挂着两套门槛 |

### 当前已知限制（写清楚，别自欺欺人）

| 限制 | 说明 |
|---|---|
| 登录**不是银行级** | 没做失败限速、没做二次验证。它挡的是「同事随手点进你的账号」，不是挡有心攻击 |
| 备份**依赖这台电脑** | 关机就不跑；且依赖 Docker |
| 红线 R2/R3 **会误报且无人能翻案** | 人工复核已取消。代价是报告里一句话说重了，不影响上岗资格 |
| 教练台格子那一层**没有自动化测试** | 纯函数部分有 160 条测试全绿，连库的那一层是空白 |
| 「一天认最早 3 局」在跨天作废场景下**可能选错** | 极低概率，在册 |

## 附录 B：符号与术语表

### 六格符号

| 符号 | 含义 | 动作 |
|---|---|---|
| `68` | 局分 | 不用动 |
| `✗`（红） | 有资格却没考 | **催考试** |
| `锁`（橙） | 那天没资格考（演习没练够） | **催演习** |
| `?`（灰） | 考了但没评出分 | 找开发 |
| `·`（淡） | 还轮不到 / 入职前 | 不用管 |
| 整行「请假」 | 那天不是他的业务日 | 不用管 |

### 术语

| 词 | 意思 |
|---|---|
| **演习 / 练习局** | 自己开的练手局，不进判定 |
| **考试局** | 考试闸门开出来的局，判定的唯一材料 |
| **训练期** | 没有新询盘分配权 |
| **在岗期** | 有新询盘分配权 |
| **暂停** | **只停发新询盘**，手上的客户仍归他 |
| **演习段位 D** | 演习体系的段位，D1–D5，**永不写作 L** |
| **业务日** | 由工作日历决定的上班日，不等于周一到周五 |
| **起判锚点** | 系统从这天之后才开始判他 |
| **窗口** | 最近 2 个业务日的 6 个考试局格子 |
| **红线** | R1 裸报价 / R2 疑罪从有 / R3 空催 / R4 中文作答 |
| **明牌 / 暗牌** | 明牌 = 询盘原文和平台数据里写着的；暗牌 = 客户没主动说、要业务员用对方法才解锁的 |
| **难度系数** | 调「拿到 65 分有多难」的唯一旋钮，不改门槛 |
| **证据不足** | 引文校验没过、覆盖率或维度数不够，系统拒绝出精确分 |
