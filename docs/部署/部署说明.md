# 部署说明

> 这份说明写的是**怎么把系统部署成一套能让团队在线使用的网站**。
> 本地试用只需要看 README 的「本地运行」一节。

---

## 一、系统由哪几块组成

| 部分 | 用什么 | 说明 |
|---|---|---|
| 网站 | Next.js 15（Node.js 20 及以上） | 业务员和主管都在浏览器里用 |
| 数据库 | PostgreSQL 16 及以上 | 账号、对局、评分、判定记录都存在这里 |
| 大模型 | DeepSeek（OpenAI 兼容协议） | 扮演客户、翻译、复盘提问、评分 |
| 定时任务 | 每天上海时间 00:05 调一次 `/api/settlement` | 每晚结算：收掉跨天没考完的场次、判定实习业务员准入、给正式业务员周考记账 |

> 定时任务漏跑一晚不会出事：首页和账号管理页被打开时会自动补算（幂等）。

---

## 二、选一条部署路线

| 路线 | 适合谁 | 优点 | 要注意 |
|---|---|---|---|
| **A. 托管平台 + 云数据库**（如 Vercel + Neon） | 不想自己管服务器 | 上手快，免运维 | 国外平台的默认域名在国内访问可能不稳，**一定要用手机流量实测一局**；托管平台的免费档通常禁止商业用途，商用请开付费档 |
| **B. 自己的服务器 + Docker** | 国内团队、要稳定访问 | 访问稳，数据在自己手里 | 要自己管服务器和备份 |
| **C. 内网一台常开的电脑** | 小团队、只在办公室用 | 零成本 | 电脑关机就用不了 |

---

## 三、环境变量（三条路线都要配）

复制 `.env.example` 为 `.env`，逐项填写。各项含义见 `.env.example` 里的注释，最关键的是这几项：

| 变量 | 填什么 | 缺了会怎样 |
|---|---|---|
| `DATABASE_URL` | 数据库连接串 | 网站起不来 |
| `AUTH_SECRET` | 至少 32 位随机串（生成命令见 `.env.example`） | 一登录就报错。**上线后不要再换**，换了全员要重新登录 |
| `DEEPSEEK_API_KEY` / `LLM_BASE_URL` | 模型密钥与地址 | 客户不回话、评不了分 |
| `MODEL_*` | 各用途的模型名 | 同上 |
| `BOOTSTRAP_TOKEN` | 随机串 | 路线 A 用它在线上建表、建主管账号、装入题库包；不配则该接口自动关闭 |
| `BANK_DIR` | 题库包目录（相对项目根目录） | 选填。配了，初始化时自动装入这个题库包；不配，系统以空题库启动 |
| `CRON_SECRET` | 随机串 | 定时结算接口的口令 |
| `WORKSHOP_MODE` | `full` 或 `bank-only` | 选填。题库工坊开几页：常驻服务器（路线 B、C）默认全开；Vercel 上自动只开「题库」「覆盖」两页。别的托管平台请填 `bank-only` |

**改了任何环境变量，都要重新部署或重启一次才生效。**

## 四、路线 A：托管平台 + 云数据库

1. **开一个 PostgreSQL 云数据库**，拿到连接串。应用用连接池串，备份用直连串。
2. **把代码部署到托管平台**。项目根目录已带 `vercel.json`，里面配好了每晚结算的定时任务。
3. **在托管平台里配齐第三节的环境变量**，重新部署一次。
4. **准备题库包**：两种办法任选——
   - 部署好后登录，到「题库工坊 → 题库」上传题库包目录装入（推荐）。题库包在本机用题库工坊做：托管平台的硬盘是临时的、单次请求最长 5 分钟，加工题库跑不了，所以路线 A 上工坊只开「题库」「覆盖」两页；
   - 或者把题库包目录放进部署的代码里（例如 `banks/<题库包>/`），并把环境变量 `BANK_DIR` 设为这个路径。题库包是你们公司自己的数据，部署代码的仓库请设为私有。
5. **建表 + 主管账号 + 装入题库**（在服务端执行，开发机连不上云数据库也没关系）：

   ```bash
   curl -X POST "https://<你的域名>/api/admin/bootstrap" \
        -H "x-bootstrap-token: <BOOTSTRAP_TOKEN>"
   ```

   返回 `{"ok":true, ...}` 即成功。这个接口幂等，可以反复调；同一个题库版本装两次会自动跳过，不删任何数据。
6. **函数超时**：评分要跑大模型，需要较长执行时间。在平台设置里把函数最长执行时间调到 300 秒。

以后升级版本时，数据库结构有变化的话，用直连串在本机执行：

```bash
DATABASE_URL="<直连串>" npx prisma migrate deploy
```

## 五、路线 B：自己的服务器 + Docker

服务器装好 Docker 后，在项目目录准备一个 `.env`，至少包含：

```
POSTGRES_USER=drill
POSTGRES_PASSWORD=<自己设一个强密码>
DEEPSEEK_API_KEY=<你的密钥>
AUTH_SECRET=<32 位以上随机串>
CRON_SECRET=<随机串>
```

然后：

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec app npm run seed   # 建主管账号
docker compose -f docker-compose.prod.yml cp <题库包目录> app:/app/bank   # 把题库包放进容器
docker compose -f docker-compose.prod.yml exec app npm run bank -- load bank   # 装入题库包
```

网站在 `http://<服务器IP>:3100`。要用域名和 HTTPS，在前面加一层 Nginx 或 Caddy。

**每晚结算**：服务器上加一条 crontab（服务器时区按上海时间算的话写 `5 0 * * *`）：

```
5 0 * * * curl -s -X POST -H "Authorization: Bearer <CRON_SECRET>" http://localhost:3100/api/settlement
```

## 六、路线 C：内网电脑

> Windows、Mac 都行。第一次装、不熟命令行的，按《安装说明》一步步来，最后一步用 `npm run build && npm run start` 代替 `npm run dev`。

```bash
npm install
npm run db:up        # 用 docker 起本地数据库
npx prisma migrate deploy
npm run seed
npm run bank -- load <题库包目录>
npm run build && npm run start
```

同事用 `http://<这台电脑的内网IP>:3100` 访问。

## 七、上线后第一件事

1. 确认题库已装入：`npm run bank -- list` 能看到一个带 ★ 的当前版本；没有的话首页会显示「还没有题库」的引导。
   只想先演示：装样品题库 `npm run bank -- load samples/bank`（或把 `BANK_DIR` 设为 `samples/bank`），见 `samples/README.md`。
2. 用简码 **`ADMIN`** 登录。**第一次登录时输入的口令就是以后的口令**（至少 6 位，不能是纯数字），所以要由管理员本人先登。
3. 进「账号管理」逐个添加业务员，把简码发给他们，让他们各自首登设口令。
4. 找一个业务员用手机完整打一局 20 轮，确认访问、对话、评分都正常。
5. 配好备份，见 `备份与恢复.md`。

## 八、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面能开，一登录就报错 | 没配 `AUTH_SECRET` 或不足 32 位 | 补上后重新部署 |
| 老用户突然全要重新登录 | `AUTH_SECRET` 被换了 | 换回原来的值 |
| 间歇性 `too many connections` | 云数据库用了直连串 | 换成连接池串 |
| 生成报告转半天后超时 | 函数执行时间太短 | 调到 300 秒；还不够就把 `MODEL_SCORE` 换成 flash 模型 |
| 一开局就报错 | 数据库结构没升级 | 执行 `npx prisma migrate deploy` |
| 首页显示「还没有题库」 | 没装题库包，或装入失败 | `npm run bank -- validate <题库包目录>` 看哪里不对，修好后 `npm run bank -- load` |
