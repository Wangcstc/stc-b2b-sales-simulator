# 抽屉使用说明

> 抽屉把一家公司的**原材料**加工成**题库包**，题库包再装进柜子（网站）给业务员练和考。
> 抽屉不连柜子的数据库，产出只有一样东西：一个题库包目录。

```
原材料（聊天导出件 + 产品表 + 公司信息表）
   → 抽屉：① 投料 ② 脱敏 ③ 归型 ④ 起草母题 ⑥ 质检 ⑦ 校准 ⑧ 主管确认 ⑤ 变体 ⑨ 分池 ⑩ 打包
   → 题库包 → npm run bank -- load <题库包> → 柜子
```

---

## 一、准备原材料

| 原材料 | 格式 | 从哪来 |
|---|---|---|
| 聊天导出件 | 阿里国际站聊天记录导出的 `.html`（v1 只支持这一种） | 业务员各自导出 |
| 产品表 | `standards/templates/产品表模板-v1.0.xlsx` 填好 | 必须有：价格是 AI 买家判断报价对不对的标准答案 |
| 公司信息表 | `standards/templates/公司信息模板-v1.0.xlsx` 填好 | 选填，**不填公司真实名称** |

填法见 `standards/templates/投料说明.md`；照着填好的样例在 `samples/raw-materials/`。
文件名里带「产品」的 `.xlsx` 当产品表读，带「公司」的当公司信息表读。

**聊天投多少份都行**，手上有几份就投几份：每份能用的聊天大约出一道演习题，出一道就能练一道。以后有新聊天随时再投一批，`--base` 加进旧题库。题越多，业务员越不容易撞题。
考试要每个槽位攒够题才开得了（见第六节），打包时会告诉你还差哪几类买家；差什么就留意收集什么，不用一次凑齐。

## 〇、网页还是命令行

主管日常用**网页上的题库工坊**（顶部导航「题库工坊」，只有主管和管理员看得到）：投料、加工、确认、题库、覆盖五页，所有要拍板的事都是选择题。下面写的是命令行，调的是同一套抽屉接口，结果完全一致；批量处理、运维、排查时用。

网页投料和命令行投料有一处不同：**网页上脱敏在主管自己的浏览器里完成**，服务器只收到脱敏后的内容，连原文件名都不传（换成「c001-化名」）。

## 二、配置

`.env` 里要有 `DEEPSEEK_API_KEY`。想让抽屉算钱、设预算，填上 `PRICE_FLASH_*`、`PRICE_PRO_*` 单价（元 / 百万 token，填**空闲时段**价，`.env.example` 里有抄好的当期价）和 `PRICE_PEAK_MULTIPLIER=2`（DeepSeek 北京时间工作日 9–12、14–18 单价翻倍，记账时按调用时刻自动乘；法定节假日认不出，按高峰算）。
自家的名字写进一个词表文件，用 `DRAWER_MASK_FILE` 指过去（见第七节），以后每次投料自动带上。
其余抽屉配置见 `.env.example` 末尾「抽屉」一节，都可以留空。

## 三、一批的完整流程

```bash
# ① 投料（批次不存在就新建）。--variants 每道母题衍生几道考试变体，默认 3；--budget 预算（元）
npm run drawer -- ingest 2026-11-a ./原材料/聊天 ./原材料/产品表.xlsx ./原材料/公司信息.xlsx --budget 50

# ② 脱敏当场完成。有疑似漏网人名的素材会停下来出卡，先处理
npm run drawer -- reviews 2026-11-a
npm run drawer -- answer 2026-11-a r0001 pass

# 开工前看看大概花多少
npm run drawer -- estimate 2026-11-a

# ③④⑥⑦ 加工：归型 → 起草母题 → 质检与校准（不过就自动修订，最多 3 次）→ 出确认卡
npm run drawer -- run 2026-11-a            # 先试几份：加 --limit 3

# ⑧ 主管确认。先生成审题单看题（写在批次目录里），再答卡。演习题可以批量按推荐处理，考试题必须逐道确认
npm run drawer -- sheet 2026-11-a
npm run drawer -- reviews 2026-11-a
npm run drawer -- answer 2026-11-a --all-recommended
npm run drawer -- answer 2026-11-a r0012 accept

# ⑤ 母题采用后再跑一次，生成考试变体，变体同样过质检、出确认卡
npm run drawer -- run 2026-11-a

# ⑨⑩ 分池与打包
npm run drawer -- pack 2026-11-a --version 1.0.0
npm run bank -- load workspace/banks/<题库编号>/1.0.0
```

`npm run drawer -- status <批次>` 随时看进度，`npm run drawer -- list` 列出全部批次。
修订 3 次仍没过闸的素材标为出错，看过原因后可以 `npm run drawer -- retry <批次> [素材号]` 重做（会再花一次钱）。

**花费参考**（2026-11-06 真实聊天 10 份实测，flash 归型、pro 起草）：10 份出 36 道题，99 次调用、约 41 万输入 75 万输出 token，约 13 元，即**每份聊天约 1.2–1.3 元**。高峰时段跑约翻倍，晚上或周末跑更省。`estimate` 的预估按这次实测校准过（空闲时段价）。样品聊天（每份 10–20 句）在网页上真跑：8 份 6.3 元、出 29 道题。

## 四、选择题卡

凡是要主管拍板的事，抽屉都出一张卡：**3 个选项 + 「其他」，推荐项排第一（★），并写明推荐理由**。

| 卡 | 什么时候出 | 选项 |
|---|---|---|
| 疑似漏网 | 脱敏后还有长得像人名、公司名的词 | `mask_all` 全部抹掉重跑 ｜ `pass` 都是噪音，放行 ｜ `drop` 这份不用了 ｜ `other` 写出要抹的词 |
| 要不要采用 | 一道题过了全部机器闸门 | `accept` 采用 ｜ `revise` 退回修订 ｜ `reject` 弃用 ｜ `other` 写修改意见（模型按意见改，改完重新出卡） |
| 预算 | 花费到了预算 | `raise` 预算翻倍接着跑 ｜ `stop_pack` 停下先打包 ｜ `stop` 停止这一批 ｜ `other` 写一个新预算金额 |

疑似词**全是**贸易术语、认证缩写、型号前缀（FCC、MSDS、LT- 这类）时推荐放行，否则推荐全部抹掉——宁可多抹，不能漏一个真名。

## 五、机器闸门（质检与校准）

每道题（母题和变体）进确认卡之前都要过下面这些闸，任何一项 ✗ 都退回模型修订：

1. **格式**：符合题库格式 v1（`standards/schema/persona.schema.json`）。
2. **考纲**：题型在考纲里、难度档是这一型允许的、不进考试的题型不进考试池。
3. **质量门槛**：暗牌 4–7 张、每张解锁正则 ≥2 条、正例 ≥3 句、反例 ≥2 句、干扰项 ≤5 条、开局三项在范围内（`standards/quality-rules.json`）。
4. **解锁正则**：正反例全过；普通问法不白送暗牌；普通话术不被判成泄露；干扰项和开场询盘自己不泄露暗牌。
5. **忠实度**：每张暗牌要么在素材里找得到原话，要么标明是补写的并写理由。变体一律标为「由母题改写」。
6. **一致性**：买家说出口的话不出现中文；价格档位与产品表一模一样。
7. **背调包**（只有考纲标了「配背调包」的题型，目前是身份存疑型）：题目过闸后再写一份背调包，AI 报告里预埋一个错误结论，官网、社媒、联系方式三块各留一处矛盾；它自己也要过闸——预埋错误写清楚、至少两条识破路径、答案不许发到浏览器。
8. **自动对局**：拿判定引擎把这一局机器打一遍——暗牌链走得通、好新人不会提前出局、六要素收得齐；顺手量出机制难度指数，写进确认卡。

机器闸门只能证明这道题**机制上没毛病**。好不好、像不像真人，要靠主管确认时看一眼，上线后再让真人跑几局。

## 六、分池与打包

- 母题进**演习池**；变体进**考试池**。只有能进考试、而且落得进考试槽位（探需·标准、探需·困难、跟进）的母题才衍生变体——简单档的询盘局抽不进任何槽位，不衍生。打包时，暂不进考试的题型和落不进槽位的题一律放进演习池。
- **打包时会报两件事**：演习有几道（不设下限，有就能练）；考试三个槽位各还差几道题、几种题型、还没有哪些题型。考试凑齐前照常打包、照常装进柜子，只是开不了考。门槛和柜子开考用的是同一份（`standards/pool-requirements.json`，默认每槽 ≥14 道且 ≥4 个题型）。每道母题会衍生几道考试变体，所以一个槽位大约 5 份对路的聊天就够。真实聊天里**探需·困难**这一槽最难攒（身份存疑、首响迟到、大单幻觉、同行套价、招标项目、极限压价），碰到这类买家的聊天优先投。
- `pack` 可以一次打多个批次（逗号隔开）；`--base <旧题库包>` 在旧题库上加题，编号撞了自动顺延；`--strip-source` 剥掉来源备注再对外分发。
- **题库版本号只增不减、不复用**：同一个版本号的目录已经存在就拒绝打包。

## 六点五、回流（题库上线以后）

业务员练起来之后，题库工坊的「回流」页按题统计实战表现：通过率（过 65 分算过）、平均分、红线率、客户放弃率、最弱的力、挖出率低的暗牌、是不是总被同一句话破解。
每道题攒够 10 局有分的局才判（口径在 `standards/feedback-rules.json`），异常的出选择题：

- **回炉**：把题退回抽屉，修改意见是按统计写好的（比如「通过率 100%，太容易：让关键暗牌更难挖……」），模型照着改一版、重新过闸、到「确认」页等你（卡上标出改了哪里），采用后下次打包**顶替**原题，编号不变。只有抽屉做的题能回炉；命令行等价操作没有，回炉只在网页上。
- **降为演习 / 下架**：马上生效，下次打包自动带过去（题库页手动停用的题也一样，不会因为打新版本又活回来）。
- **保留**：记下来，再攒够 10 局新数据前不再提。

同一道题跨版本合并统计；回炉改过暗牌的，只算改过之后的局。

## 七、隐私

- **自动抹掉的**：买家和业务员的名字（含替班同事、买家那边换人说话的发送人，两三个字母的姓，中文名）、公司名、邮箱、网址（带不带 http 都算）、邮箱和网址里的域名品牌词（`buyer@acmecamp.example` → 正文里的 AcmeCamp 也抹）、电话（含括号区号、点号分隔、四段以上）、即时通讯账号、证件号、税号、地址（中英文，含「××路 88 号」）、中文公司名、邮编、生日、订单号与货件号、运单号。国家、城市、品类、价格、时间节奏保留——那是训练价值。
- **自家的名字要显式列出**：公司中英文名、品牌名、业务员的英文名和小名、工厂所在城市，正则抓不到。写进本批脱敏词表：命令行 `--mask "名1,名2"`，或者词表文件 `--mask-file <文件>`（一行一个词，`#` 后是注释，可写「原词=替换词」；中文两个字、英文两个字母的词也认，两个字母的只按整词抹）。在 `.env` 配 `DRAWER_MASK_FILE` 后每次投料自动带上。词表只存在工作区，只用于脱敏，不进题库包；**词表文件本身也别放进仓库**。没带词表投料时会提醒。
- **抓不到、要靠人看的**：正文里顺口提到的第三方人名（「my boss John」）、不在任何邮箱网址里出现的大小写混写品牌名。全大写的会进「疑似漏网」卡；其余靠审题时看一眼，看到了就把它加进词表、这批删掉重投。
- 已经脱敏过的素材（`redacted.json`）也可以投，投料时会按当前规则和词表再补跑一遍。**旧版脱敏的素材一定要带上词表再投**，旧版规则漏过品牌名和货件号。
- 抽屉只**复制**你给的原始导出件，不动原文件。收件箱里的副本在整批都脱敏通过后删除（`--keep-raw` 可保留）。
- 真名与化名的对照表不落盘，脱敏后的素材不可还原。
- `workspace/` 整个目录在 `.gitignore` 里，永远不进仓库——里面是你们公司自己的数据。
- 来源备注 `_source` 只记素材编号（如 `2026-11-a-m003`）和脱敏后的原话，不记日期、条数、成交结果。

## 八、中断与重跑

所有状态都落盘在 `workspace/drawer/batches/<批次>/`。`run` 随时可以 Ctrl+C，再跑一次只做还没做完的事，已经花过钱的步骤不会再花。
