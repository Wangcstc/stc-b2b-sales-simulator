# 题目编写须知（题库格式 v1）

> 写一道题（人设）之前必读。题目的格式规范是 `standards/schema/persona.schema.json`，
> 题型规范是 `standards/syllabus/README.md`（考纲 v3，55 型）。以下路径都相对项目根目录。

---

## 一、你要交付什么

一份题目文件 `personas/<题目编号>.json`，放进一个题库包目录里，结构符合题库格式 v1，并且过下面四道闸：

```bash
# ① 结构 + 考纲 + 引用（整个题库包一起校验）
npm run bank -- validate <题库包目录>

# ② 解锁正则：该解锁的解锁、不该解锁的不解锁、普通话不会被判成泄露
npx tsx scripts/import/verify-persona.ts <题库包目录>/personas/<你的文件>.json

# ③ 忠实度：暗牌是素材里真有的，还是编的
npx tsx scripts/import/verify-fidelity.ts <题库包目录>/personas/<你的文件>.json --materials=<脱敏素材目录> --strict

# ④ 自动对局：整局打不打得通
npx tsx scripts/import/autoplay.ts <题库包目录>/personas/<你的文件>.json
```

**四道都必须 `硬问题 0 处`**，没通过就不算交付。

### 编号与题型

- 题目编号：`<题型编码>-<国家两位代码>-<三位序号>`，例：`A09-PL-001`；国家不明用 `XX`。
- `skeleton.type_code` 写考纲的题型编码，`skeleton.name` 写**考纲里的题型名，一字不差**（装入时会核对）。
- 变体（同一题型的另一个化身）也用独立编号，用 `derived_from` 指向母题。

### 忠实度：每张暗牌都要交代来历

评分侧要求每一力打分都附「第几轮、原话」；出题侧一样，每张暗牌都要在顶层 `_source` 里交代出处：

```jsonc
"_source": {
  "material_id": "<脱敏素材编号>",
  "quotes": [
    { "card": "H1_two_of_each_means_twelve", "message_index": 32, "quote": "Can I get 2 of each" },
    { "card": "H4_retail_band", "invented": true, "why": "素材里客户一次都没谈过价格，零售区间按同品类公开数据补，用途是让『不给目标价』这个考点有一个可推算的锚。" }
  ]
}
```

- `message_index` 是素材对话里第几条消息（从 0 起），`quote` 归一化后必须能在那条消息里找到。
- **补的牌要明说，不许沉默**：写 `invented: true` 并写 `why`。只写 `invented` 不写理由，闸会当硬问题拦下。
- **只记编号和出处**：不写素材的日期、条数、国家、成交结果，不写「真实那局」这类描述。导出题库包给别人时，`_source` 可以整段剥掉。

### 自动对局查什么

暗牌的 `requires` 链走不走得通；好新人规规矩矩打会不会活不到干完活；六要素在这一局收不收得齐；
以及**买家会原样说出口的台词（`exit_lines` / `quote_reactions` / 干扰项 / 开场询盘）有没有自己泄露暗牌**。

**开局 `init_state.patience` 定低了会直接导致这局打不通。** 参考算法：
六要素轮数 + 暗牌张数 ≈ 干完活要的轮数，每轮固定衰减 -5。实测最低可玩是 40，拿不准就先写 60，自动对局过了再往下调。

最后回报：文件路径、四道闸的结果、你做了哪些**变体参数**改动、以及你拿不准需要人裁的地方。

## 二、先读这三样，顺序别乱

1. **该题型的规范**：`standards/syllabus/README.md` 里你这一型的那一节——考点、主考力、满分动作、典型失分、暗牌设计要点。
2. **母题**（任务里指定的那道题）——从头到尾读完，别跳。
3. **素材**（任务里指定的脱敏对话）——真实聊天记录，已脱敏，是这道题的现实依据。

## 三、★ 考试变体的铁规矩 ★

考试变体 = **同一个题型的另一个化身**。

**必须原样保留（改了就是改考点，不许）**

- `skeleton` 整块（题型编码、题型名、局型、难度、考什么、七力）
- 每张暗牌的 `requires` 依赖关系、`unlock` 判定口径（**谁问对了才给**这件事本身）
- 暗牌的 **key 名**——除非 key 里嵌了变体细节（`H3_yiwu_consolidation`、`H5_540_pcs` 这种），
  那种情况跟着内容改名，并在 `_variant_diff` 里记一笔。**留着一个名实不符的 key 比改名更糟**
- `unlock_patterns` / `unlock_patterns_topic` / `unlock_patterns_framing` —— **除非新变体的措辞让某条正则失效，否则一个字都别动**
- 暗牌张数、`leak_fallback` 的性质、`followup_reactions` 的机制（跟进局）

**必须换掉（不换就是换汤不换药，防背题失效）**

- `id`：新编号；`derived_from`：母题编号
- `open_card`：人名、公司、国家、邮箱、`categories`、`login_days_90d`、`product_views_90d`、`registered_at`、`inquiry_text`
- `product`：`model`、`name`、`attributes`、`page_price`、`price_tiers`、`surcharges`——**换品类，不是改个数字**
- 每张暗牌的 `value`（具体内容）与 `leak_signals`（信号必须跟着新 value 走，旧变体的地名月份数字留着就是死信号）
- `distractors` 的 `content`
- `exit_lines`、`quote_reactions` 的措辞
- `verify_cases` 里的例句（正反例都要贴合新变体的产品与措辞）

**必须写**

- `"pool_type": "admission_exam"`（考试题）或 `"drill"`（演习题）。风险识别型（G01–G04）暂不进考试，只能写 `drill`。
- 顶部 `_comment` 说明「派生自 <母题编号>（<题型名>）。暗牌机制、考点、扣分口径与母题一致」。

### 题型不是题目能改的

题型的名称、考点、局型、默认难度、七力都由考纲决定，装入时题型行一律按考纲写，题目里的 `skeleton` 只是标明自己属于哪一型。
**不要新建题型**：找不到能挂的题型，说明这份素材要么该换个角度写，要么该提新增题型的建议——那由王老师拍板、升考纲版本，不是写题时顺手能做的。

## 三点五、★ 难度：可以挂在题目上 ★

同一个题型可以出不同难度的题。题目顶层写 `difficulty` 就覆盖题型的默认档位：

```jsonc
{
  "id": "A04-US-003",
  "difficulty": "hard",          // ← 题目级覆盖。不写＝跟题型默认档位走
  "skeleton": { "type_code": "A04", "name": "定制深挖型", "difficulty": "standard", ... }
}
```

### 调难度就调这六个旋钮

| # | 旋钮 | 调它等于调什么 |
|---|---|---|
| 1 | 暗牌张数 + `requires` 链最长深度 | 要问出多少东西、有没有必须先问 A 才能问 B 的次序 |
| 2 | 解锁严格度 | 单组 `unlock_patterns`（宽）→ `topic` + `framing` 双组（严，裸问不给）→ 再加前置牌（最严） |
| 3 | 开局三值 `patience` / `trust` / `interest` | 容错轮数。每轮固定衰减 5，耐心 60 ≈ 12 轮容错，40 ≈ 8 轮 |
| 4 | 干扰项密度与迷惑性 | 噪音里要不要做判断，还是只要听清楚 |
| 5 | 六要素可得性 | 客户主动给几项 / 要问几项 / 有几项客户会含糊其辞 |
| 6 | 离场触发宽严 | `maxTurns`、连续无新信息的 `stagnant` 阈值 |

### ★ 声明了覆盖，就必须真的拉开 ★

自动对局的闸⑧ 会拿**机制难度指数**去验：这道题和同题型、没声明覆盖的兄弟们
差了多少。差不到 **12 分**就是硬问题：

```
✗ A04-US-003 声明「hard」（题型默认「standard」），但机制难度只差 4 分
    （本份 38，同题型其他题中位 34，至少要差 12）。
    换汤不换药的「困难版」会让困难槽名义上有题、实际考的是标准难度。
```

只把字段从 `standard` 改成 `hard`、机制一个字没动——那不是派生了一档，
是往困难槽里塞了一道标准题，而**「困难局撑不撑得住」正是准入要判的东西**。

**实测标定（记在这儿省得你摸索）**：

| 动了什么 | 与兄弟中位数的差 | 结果 |
|---|---|---|
| 只改 `difficulty` 字段 | 0 | ✗ 拦下 |
| 开局耐心 55 → 40（**拧一个旋钮**） | 11 | ✗ 还是拦下 |
| 耐心 55 → 40 **且** 干扰项 2 → 4（**两个旋钮**） | 13 | ✓ 过 |

**一个旋钮拧到底通常还差一点，得动两个。** 这是有意的——同一考点内部天然的
指数波动大约在 ±5，门槛定在 12 就是要求「明显跳出噪音」，而不是「比兄弟略高一点」。

### 机制难度指数不是档位标签

跑 `npx tsx scripts/import/autoplay.ts <题库包>/personas --report` 看全池分布。要先知道一件事：

```
声明「simple」  18 份 ｜ 实测 40–58 ｜ 中位 50   ← 机制上最重
声明「standard」88 份 ｜ 实测 19–47 ｜ 中位 34   ← 机制上最轻
声明「hard」    40 份 ｜ 实测 20–55 ｜ 中位 41
```

**声明的「简单」档在机制上恰恰是最难的那一档。** 这不是错——两把尺量的不是同一个东西：

- **标签量认知难度**：这个题型本身难不难想明白。简单档（配合探需型、语言错位型、答非所问型）考的是
  「先把话听清楚」，认知上最浅；可它们每份带 7 张暗牌、5 条干扰项，机制上一点不轻。
- **指数量机制难度**：跑通这一局要几轮、耗掉多少容错、卡不卡得住。

所以**别拿指数去判某份题该是哪一档**。它只做两件事：验证同考点两档真的拉开了；
在报告里给分布供人判断。改档是人的事，而且**改档会改变考试槽位的份数**——
考试池有「每槽 ≥14 份、≥4 个考点」的硬门槛，改错一档可能让全员当场开不了考。

## 四、暗牌与正则的三个坑（都是这个仓库真栽过的）

1. **JSON 里的 `\b` 是退格符，不是词边界。** 必须写 `\\bFOB\\b`。少一层转义，正则永远匹配不上，而且肉眼看文件完全正常。verify 的「转义检查」专抓这个。
2. **`leak_signals` 按字面子串匹配，不是正则。** 里面不许出现 `\b` `[` `(` `|` `*` `+` `?`。也别写 ≤3 个字母的纯英文短词，会在别的单词里误命中。电话号码别带 `+`（写 `44 7700` 而不是 `+44 7700`，这样 `0044`、`(44)` 几种写法都能覆盖）。
3. **正则里的裸词会在别的单词内部命中。** 这个仓库的引擎按子串匹配，`ce` 会命中 `price`、
   `pi` 会命中 `shipping`、`ok` 会命中 `broken`。实测已经因此白送过 7 次暗牌，其中最离谱的一次：
   客户说 "The goods arrived broken" 反而解锁了「轻微破损客户自行吸收」——语义整个反了。
   **凡是 ≤3 个字母的英文缩写，一律写成 `\\bCE\\b` `\\bPI\\b` `\\bLC\\b` 这种带词边界的形式。**
   写完用 `verify-persona` 跑一遍，它会拿一套普通话术检查有没有误解锁、误判泄露。
4. **topic 组和 framing 组会互相塌陷。** 两组都命中才解锁的设计，如果 framing 组里写了 `hold` 这种裸词，会被 topic 组里的 `holding` 子串命中，两组机制直接合成一组——一句空洞的 "What is holding you back?" 就把牌开了。framing 组要写**真正的由头动作**（预留库存、备料、发实物图、报进度），不是情绪词。

`verify_cases` 的反例就是用来钉死这几个坑的：**每张暗牌至少 2 条反例**，其中一条必须是「近义但不达标的问法」（裸问决策人、空洞追问、只问自己那边的事）。

## 五、不许碰的三条铁律（全仓通用）

1. 演习分数叫**演习段位 D**，**永不写作 L**。题目文件里任何地方都不许出现把段位写成 L1/L2/L3 的表述。
2. 演习局**不得写入** `wang-grade-coach-memory`，题目里不许出现任何往那边写数据的字段或说明。
3. 考试通过的结论只有一句：**「已获得询盘接待准入资格」**，不得表述为「达到 L2/L3」。

`npm run lint:l-word` 会扫这个，别踩。

## 六、素材怎么用

素材是**现实依据**，不是照抄对象。

- **要保留的**：国家、品类、数量级、时间节奏、客户的语言风格（句子长短、礼貌程度、母语痕迹）、失单发生在第几轮、客户真正卡住的点。这些是训练价值本身。
- **要翻转的**：素材里客户**主动说出来**的信息，在题目里要变成「**问到才给**」的暗牌。这是素材到题目最关键的一步——客户不会主动交底，新人得问出来。
- **要补的**：素材里没有的价格阶梯、加价项、干扰项，你按同品类的合理商业逻辑补，并在 `_source` 里标成 `invented` 写明理由。
- **不许做的**：素材里的化名已经是脱敏后的化名，**不要直接沿用**——题目是要发给全公司新人看的，再换一层名字。国家可以保留。

素材里 `digest` 字段有回合数、成交状态、时间跨度，先看它再决定读多细。

## 七、写作口径

- 中文注释字段（`_comment`、`_xxx_note`）用这个仓库的语气：**直接说结论和原因，说清楚"为什么这么设计"和"不这么设计会怎样"**，不写"我建议""我们可以考虑"。
- 客户说的英文要贴合国别（西非客户的英语、德国买家的英语、拉美买家的英语，句式和礼貌程度都不一样），`language_style` 字段要把这个写清楚。
- 数字不许编得离谱：单价、MOQ、箱规、交期要符合该品类的真实商业常识。拿不准的写进回报里，别硬编。
